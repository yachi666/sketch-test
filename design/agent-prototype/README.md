# SketchTest · Agent 配置与用例溯源交互原型

独立前端原型，设计依据位于 `references/`，不接入 Control Plane、AI Worker、真实模型或 Runner。所有连接验证、生成耗时、tokens、模型 ID、用例内容均为明确标注的示例。数据只存于内存，刷新恢复初始状态。

## 已实现的交互

- 独立的 Agent 管理：搜索、创建、启停、厂商/模型/连接联动、职责、超时和重试、保存新版本、历史版本。
- 厂商连接：示例连接新增与测试；只接受凭据引用，不采集真实密钥。
- 智能生成：按能力筛选启用的 Agent，冻结本次配置，模拟阶段进度，取消演示，生成待审核草稿，查看任务详情。
- 用例管理：审核/拒绝 AI 草稿，接受为用例草稿，编辑请求和状态码，独立发布。
- 用例详情：生成来源、人工修改沿革、执行详情抽屉。
- 执行详情：事件阶段、输入与来源、原始产出、当时 Agent 的只读配置。后续编辑不会改写来源。
- 桌面布局和窄屏导航、表单与抽屉。

入口：Agent 管理 → 智能生成 → 审核草稿 → 用例详情 → 查看 Agent 执行详情。

## 本地运行

```sh
npm install
npm run dev -- --host 127.0.0.1 --port 4317
```

稳定预览：

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4318
```

## 范围与后续产品接入

这是交互设计交付，生产代码未改变。生产接入需要在版本化 contracts 后实现 Agent 配置版本、厂商密钥引用、显式模型选择、任务事件与产物关联；持久化的执行快照应保存实际厂商/模型返回身份，不能由当前 Agent 配置推断。模型供应商未提供底层快照版本时明确显示“厂商未返回”。

测试计划等其它业务页面可复用相同的来源摘要及执行抽屉模式。本轮仅打通已确认的用例路径；无真实模型调用、网络请求执行、鉴权权限、数据库或永久存储。导航中其余产品入口保留视觉上下文并禁用。

验证与截图见 `design-qa.md` 和 `evidence/`。
