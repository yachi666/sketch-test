# AI 主动生成测试计划

日期：2026-09-28。用户选择 Product Design 方案 3：左侧对话，右侧可编辑计划。

## 需求与交互

用户从 GitHub 仓库生成用例后，需要决定哪些已发布用例一起回归、还有哪些缺口、采用什么门禁。测试计划页默认进入 AI 建议；原有手动管理通过“已发布计划”进入。

1. 开启自动建议后，已发布用例、已发布流程或待审草稿变化会触发新建议。首次开启也会分析当前资产。
2. AI 选择执行成员，解释来源，单独列出待补齐草稿、门禁和执行前提。
3. 用户可以对话修改范围，也可以直接编辑名称、目标、成员和门禁。对话生成新版本建议，保留之前的记录；定时刷新不会切走正在编辑的建议。
4. 保存仅保存草稿；审阅发布固定已发布成员和门禁；执行继续使用已有计划执行流程。

自动建议默认关闭。这里的触发源是平台内测试资产变化，并非 GitHub webhook 或任意代码提交。模型没有发布、执行或调用业务 API 的工具。

## 实现边界

- 新增独立的 `sketch-test.plan-generation/v1` 契约。CP 提供经过裁剪的资产快照，Worker 使用真实 Pi Agent 的 `propose_plan` 工具，CP 二次验证后保存。
- 快照最多包含 75 个已发布测试、25 个已编译流程和 50 个待审草稿；按资产 ID 稳定排序。超过上限的资产不参与本次分析，不能宣称全量覆盖。
- 传递名称、方法/路径、风险、版本等元数据，不传递环境变量值、请求体、请求头或原始仓库代码。自然语言目标同样会发送给已配置模型。
- AI Worker 必须在线并声明 `plan` 能力。启用工作区每 30 秒检查一次来源哈希；当前快照不重复生成。UI 每 4 秒读取状态。
- 独立的 token 鉴权、工作区隔离、30 秒 fenced lease、最多 3 次领取、来源/输入哈希、显式模型目标。完成回调幂等，晚到失败不能覆盖成功。
- 保存使用乐观 revision。发布在事务中检查当前已发布来源版本，拒绝空成员；生成 TestSuite 和不可变 v1，不创建运行。
- 当前列表保留最近 30 个任务，对话展示最多 8 个祖先节点。旧任务仍在数据库中。
