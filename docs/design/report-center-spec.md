# 报告中心与报告详情页面规格

## 目标

让测试负责人在列表页快速确定需要处理的业务场景，让开发在详情页仅依赖脱敏、版本化证据完成复现。报告的事实结论由执行结果和断言产生；Agent 只提供带证据引用的辅助定位建议。

## 信息架构

| 路由 | 对象 | 用户任务 | 不应出现的内容 |
| --- | --- | --- | --- |
| `/reports` | 场景回归报告列表 | 查找一个业务场景的回归结论并进入详情 | 步骤证据、响应正文、Agent 结论正文 |
| `/reports/:runId/:workflowId` | 单一业务场景报告 | 判断失败事实、检查过程证据、复制重现命令 | 其他场景列表、批次级汇总表 |

## 状态模型

### 断言结果（业务事实）

- `断言通过`：执行完成，全部已执行断言满足预期。
- `断言未通过`：执行完成，至少一个断言与预期不一致。
- `未评估（执行异常）`：没有可计算的完整断言结论；不得显示为断言失败。

### 执行状态（过程事实）

- `执行完成`
- `被跳过`
- `执行异常`

断言结果与执行状态必须使用独立字段、独立视觉标签和独立筛选条件，避免将业务回归与 Runner、网络或环境问题混为一类。

## 列表页

### 最小字段

1. 业务场景（BP ID、场景名、运行批次、Git SHA）
2. 断言结果
3. 执行状态
4. 环境
5. 触发时间
6. 证据状态
7. `查看报告`

### 交互

- 搜索：业务场景名、BP ID、运行批次。
- 筛选：断言结果、环境。
- `查看报告`：进入详情页；返回后保留列表筛选和分页状态（接入真实路由状态时实现）。
- 失败行仅可显示一个灯泡图标，表示有 Agent 辅助建议；不得展示或替代断言结论。

## 详情页

### 先后顺序

1. 固定事实：断言结果、失败表达式的期望值与实际值。
2. 过程状态：执行是否完成、开始/结束时间、总耗时。
3. StepRun 时间线：所有步骤及失败步骤。
4. 证据：脱敏请求、响应、断言、变量来源、脱敏 curl。
5. 追溯：RunSnapshot、各输入版本、Git SHA、Runner/规则引擎、Trace、证据清单哈希和保留策略。
6. Agent 建议：默认折叠，显式标为“非执行结论”，且列出 StepRun/Trace 引用。

## 验收标准

- 用户在列表页无需进入详情即可区分“断言未通过”和“未评估（执行异常）”。
- 用户在详情页可看到导致结论的失败断言、全部 StepRun 与脱敏复现命令。
- 每份详情包含输入版本、环境、Git SHA、Runner、Trace 与证据清单哈希。
- Agent 输出无法改变、覆盖或模糊断言结果。
